Git How-To
(Christian's basic guide to working with Git)
		

CLONING A REPOSITORY
Navigate to the directory where you wish to clone the repo. 
	ex. cd ~/GitHub

1a. Using Git: git clone git@github.com:ORGANIZATION/REPO_NAME.git
	ex. git clone git@github.com:SkyTruth/mtm

1b. Using GitHub CLI (if installed): gh repo clone ORGANIZATION/REPO_NAME
	ex. gh repo clone SkyTruth/mt


OPTIONAL: VIRTUAL ENVIRONMENTS
These are not related to git, and may not be required or wanted based on the project. 
1. Make a new venv (with conda and setting python version to 3.14)
	ex. conda creaete --name VENV_NAME python=3.14

2. To begin work, activate the venv, nav to project Directory


BRANCH MANAGEMENT
1. Check current branch with: git status
	- to check all available branches: git branch -a

2a. Make new branch and switch to it with: git switch -c BRANCH-NAME

2b. Make new branch and stay on current branch with: git branch BRANCH-NAME

3. Change to an existing branch: git switch BRANCH-NAME


WORKFLOW
1. Work on branch

2. Stage Chages. To add changes to a future push with: git add FILENAME
	ex. changes made to requirements.txt >> git add requirements.txt

3. Commit the change with a message: git commit -m "Message here...."
   This saves staged changes. Message should be descriptive
	ex. git commit -m "Updated the requirements.txt to include selenium" 

4. Push the branch back to remote: git push --set-upstream origin BRANCH-NAME 
   This is a way to backup current progress on a branch AND to prep for a Pull Request. 
   It this backs up progress on the current local branch (BRANCH-NAME) to the remote 
   branch sharing that name, and links them. "--set-upstream origin BRANCH-NAME" only 
   needs to be included for the first time pushing a branch, afterwords only "git push" 
   is needed.


PULL REQUESTS
When the work on the branch is finalized and ready to be incorporated into the main 
branch of the repo, open a pull request so the code can be reviewed.
1. Go to the GitHub project page to make the pull request
2. After the PR is approved, from the GitHub page run:Squash and Merge
3. Post-PR, delete the remote branch from the local branch:
	3a. git fetch --prune
	3b. git branch -D BRANCH-NAME


UPDATE THE LOCAL REPO
1. Switch to the main branch: git switch main

2. Make sure local repo is up-to-date with: git pull


BRING CHANGES FROM MAIN TO THE CURRENT BRANCH
	1. git fetch origin
	2. git merge origin/<main-branch>
		--> if conflicts exist: fix the files, then git add + git commit 
		--> to exit a merge conflict: git merge --abort
	3. Back-up updated branch to remote: git push 


MISCELLANEA
Alias Commands I've made, if you're inclined to add them to your own .alias file
        1. alias g-add="git add"
        2. alias g-com="git commit -m"
